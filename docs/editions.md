# pixmint Editions — 同じ作品を N 枚出す（設計のメモ）

2026-10-25 メモ。まだ作らない（masa さん「今はまだ」）。始めるときはここから。

## 今の状態

- pixmint は **1/1 だけ**。v4（`contracts/PixMint4.sol`）に「同じ作品を N 枚」の仕組みは無く、あとから足せない。
- v4 は 2026-10-25 に乗り換えたばかり（v3 は Genesis として閉じた）。v5 に作り直すとコレクションがまた分かれる。

## 方針: エディション専用のコントラクトを足す（B 案）

v4 はそのまま。**v4 の作品を元に、版を出す別のコントラクト**（例: `PixmintEditions`）を各チェーンに置く。

- **絵はもう一度保存しない。** v4 の `data(id)`・`svg(id)` はほかのコントラクトからも読める。エディションのコントラクトは v4 の作品番号だけを覚え、tokenURI のたびに v4 から読んで組み立てる → 2 枚目からのミントがとても安く、フルオンチェーンのまま。
- **出せるのは v4 の作品の作者だけ。** `works(id).creator == msg.sender` をチェーンの上で確かめる。
- **スタンプの分配も引き継ぐ。** v4 の `stampArtists(id)` を読めば、エディションが売れたときにも 8% を分けられる（v4 と同じ計算）。
- OpenSea では別のコレクション（例: 「pixmint Editions」）。1/1（pixmint）と版もの（Editions）が分かれて見える。

## 決めること

- [ ] **ERC-721（1 枚ずつ番号。「#3 / 50」）か ERC-1155（同じものを何枚も持つ）か** — pixmint らしいのは ERC-721 の案
- [ ] **売り方**: 作家が値段と枚数（限定数）または期間（オープンエディション）を決め、買う人がその場でミント
- [ ] **お金の流れ**: mederu 2.5%・スタンプの作者 8%（人数で等分）・残りが作家、で v4 と同じにするか
- [ ] **転売**: エディションの 1 枚を pixmint の中で売り買いできるようにするか（v4 と同じ内訳）
- [ ] **ガスの上限**: tokenURI が v4 の svg を呼ぶ分だけ重くなる。最悪の作品（2,048 ラン・スタンプ 16 個）＋エディションの JSON で、上限 16,777,216 の 85% 以下に収まるかを測る（v4 の最悪は 83%。余裕が少ないので、エディション側の JSON は短く）
- [ ] **元の作品が 1/1 として売られたあと**: 作者は持ち主でなくても版を出せるか（作者の権利として出せる案が自然）
- [ ] **サイト**: 作品ページに「エディションを出す」（作者だけ）・「エディションを買う」、MINTED にエディションの表示
