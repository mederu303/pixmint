# pixmint v4 — スタンプを作品として出す（設計の下書き）

2026-10-25 下書き。まだ決定ではない。決まったところから「決定」に書き換える。

## やりたいこと

- 作家が **8×8 か 16×16** の絵を「スタンプ」としてミントする。スタンプは pixmint の作品（NFT）そのもの。
- ほかの作家が Pix でそのスタンプを使って描き、ミントすると、**使ったスタンプがチェーンに記録**される。
- その作品が **売れたとき**、売値の一部が **スタンプの作者** に入る。
- 作品の trait に **Stamp（スタンプの名前）** と **Stamp Artist（スタンプの作者）** が載る。

## お手本: mederu の素材（material）

mederuX `packages/core/src/utils/index.ts` の `buildListingShares`・`constants` で確認（2026-10-25）。

| 項目 | mederu |
|---|---|
| 払うとき | **売れたとき**（objkt の出品の shares に入れる → 一次も二次も毎回） |
| 素材の作者の取り分 | **合計 8% 一律**（`MATERIAL_SHARE_TOTAL_BP = 800`） |
| 分け方 | **使った素材の作者の人数で等分**（`floor(800 / 人数)`） |
| 外す相手 | SYSTEM の素材・運営・**売り手自身** |
| 運営 | 2.5%（`PLATFORM_FEE_BP = 250`） |
| trait | `Material`（素材の名前）・`Material Artist`（素材の作者） |

pixmint もこれに合わせる（masa さん: 「使用料は一律で使用アーティスト数で分配。mederu の material と同じ考え方」）。

## 決定（2026-10-25 masa さん）

- 受け取るのは **スタンプを作った人**（今の持ち主ではない）。スタンプを売っても、使用料は作者に入り続ける。
- 使用料は **一律**。スタンプごとに値付けはしない。**使ったスタンプの作者の人数で等分**。
- スタンプの大きさは **8×8 と 16×16 だけ**（Pix で ×2 にすれば 16・32 になる。オンチェーンの容量・SVG を組み立てる重さを抑える）。
- trait に **スタンプの名前と作者** を載せる。
- スタンプの NFT も **ふつうの作品と同じ扱い**（作者のロイヤリティ・売り買い・2.5% の手数料）。
- Pix のスタンプの一覧は **公式の下に、みんなのスタンプが随時追加** されていく形。一覧の UI は使いやすく作り直す。
- **公式スタンプの分は mederu に入る。** 公式の 12 種類も v4 でスタンプとしてミントし直し、作者 = mederu のアドレスにする。仕組みはみんなのスタンプと同じで、人数で等分するときも mederu を 1 人として数える（mederu の素材では SYSTEM を外していたが、pixmint では外さない）。
- **Pix の UI: スタンプのツールを選んだら、その下（色・サイズ・パレットの欄）が全部スタンプの一覧になる。** 公式の 12 種類が上、その下にみんなのスタンプ。色パレットはスタンプ中は出さない（masa さん 2026-10-25、スクリーンショットで指定）。
- 1 作品のスタンプの上限は **ガスの上限との兼ね合いで決める**（masa さんの目安: 15〜20 個）。`test/run.mjs` で最悪の場合を測ってから決める。

## 仕組み（案）

### スタンプのミント

```
mintStamp(bytes pxm, string name)   // size は 8 か 16 だけ受け付ける
```

- ふつうの作品と同じく SSTORE2 に保存し、同じ id の並びで ERC-721 を発行する。`works[id]` に `isStamp` の印。
- スタンプも作品ページを持ち、売り買いできる（持ち主は変わっても、使用料の受け取りは作者のまま）。

### スタンプを使った作品のミント

```
mint(bytes pxm, string title, uint16 royaltyBps, uint256[] stamps)
```

- `stamps` = 使ったスタンプの id。Pix がスタンプのボタンで押したものを自動で集める（重複は除く）。
- コントラクトで確かめること: id がスタンプであること・重複が無いこと・**数の上限**（案: 8 個）。
- 作者の一覧（重複を除いた作者）を作品ごとに保存する。**ミントした本人のスタンプは外す**（自分に払わない）。

### 売れたときの分け方（pixmint の中での売買）

今の `buy()` の内訳に、スタンプの作者の分を足す。

| 行き先 | 率 |
|---|---|
| mederu 手数料 | 2.5%（今と同じ） |
| 作品の作者のロイヤリティ | 作者が決めた率（今と同じ・作者自身が売るときは無し） |
| **スタンプの作者たち** | **合計 X% を人数で等分**（mederu に合わせるなら 8%） |
| 売り手 | 残り |

- 売り手がスタンプの作者のひとりなら、その人は分ける相手から外す（mederu と同じ）。
- 払えない相手（受け取りで失敗するコントラクトなど）は、今の `pending` に積んで、あとで本人が引き出す（今と同じ）。
- 端数（等分の余り）は売り手に入れる。

### OpenSea など外での売買（未決）

ERC-2981 の `royaltyInfo` は **受け取り先が 1 つだけ**。スタンプの作者に分けるには工夫が要る:

1. **pixmint の中での売買だけ分ける**（いちばん簡単。外での売買は今どおり作品の作者だけ）
2. **作品ごとに小さな分配用コントラクトを作る**（Clone で 1 作品 数万ガス）。`royaltyInfo` の受け取り先をそれにし、入ったお金を作者・スタンプの作者で分ける。マーケットプレイスがロイヤリティを払う場合だけ効く
3. 受け取り先を pixmint 本体にして、引き出すときに分ける — 入金にどの作品の分かが付いてこないので **できない**

→ まず 1、必要になったら 2 を足す、が現実的。

### trait（tokenURI の JSON）

```json
"attributes": [
  { "trait_type": "Stamp", "value": "heart" },
  { "trait_type": "Stamp Artist", "value": "mede☆nyan" },
  ...
]
```

- スタンプの名前は、スタンプのミントのときの `name`。
- 作者名は **チェーンにある表示名**（`displayName`）。無ければ短いアドレス。ENS はチェーンの中から引けない（tokenURI はコントラクトだけで作る）ので使わない。
- 使ったスタンプが多いと JSON が長くなる → スタンプの数の上限（案: 8）で抑える。

## ガス・容量の見積もり（要計測）

- 16×16 のスタンプ: PXM で多くて数百バイト。ふつうの作品より安い。
- 作品のミント: スタンプ 1 個につき、記録の分の数千〜2 万ガスほど増える見込み。
- `buy()`: スタンプの作者 1 人につき送金 1 回ぶん増える（上限 8 人）。
- `tokenURI`: trait の文字列ぶん増える。最悪の作品（2,048 ラン）＋ スタンプ 8 個でも、ガスの上限 16,777,216 に余裕で収まるかを `test/run.mjs` で確かめる。

## 正直に書いておくこと

- **ピクセルの丸写しは防げない。** スタンプと同じ絵を手で描けば、記録されずに使える。pixmint にできるのは「スタンプのボタンで押したものは自動で記録・自動で払われる」「作品ページに元のスタンプと作者を出す」まで。
- 記録は **ミントした人の申告**。コントラクトは「その id がスタンプであること」は確かめられるが、「絵の中に本当に入っているか」は確かめない（ピクセルの照合はガスが重すぎる）。

## v3 との関係

- v3 の作品はそのまま。v4 は新しいコントラクトとして別のアドレスに置く。
- サイトは v3 と v4 の両方を読んで並べる（MINTED・作品ページ）。
- エディション・アニメーションも v4 に入れるなら、この設計書に足す（入れる順: エディション → スタンプ → アニメーション、の案）。
